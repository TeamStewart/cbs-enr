CBS election desk · TX precinct model

How the TX precinct model behaves as votes come in

Two tests of the same model code (scripts/model/model_core.R). Each chart shows the model's estimate of the Democratic two-party share, its 95% interval, the raw share of votes counted so far, and the true final result.

    Test 1 · real election

    Backtest: 2022 governor in our 32 counties

    The model is fit to the real 2022 result using only information available before November 2022: 2020 Senate results as the partisan baseline, 2018 turnout, and L2 demographics. Precincts are then revealed in order and the estimate is checked against the known result at each step. Texas has no precinct results by vote mode, so this test treats each precinct as one unit.

    "Small counties first" reveals whole counties from smallest to largest, so Harris, Dallas, Bexar and Travis come last. That is harsher than a real night, where early votes from every county arrive within about an hour, and it isolates one problem: the first counties in are rural and Republican, so the model can read their lean as a statewide pattern. Compare the first two buttons to see what the county effect adds.

    Test 2 · simulated night

    Ethan's simulated election night ()

    Ethan's simulation produces the final count for all 6,134 precincts and a reporting schedule by vote mode: early votes in one countywide dump after polls close, Election Day precincts over the next few hours, and late mail days later. Some precincts never appear (unmatched IDs) and some counties may never report, as set in the scenario's manifest. The model is refit every 15 minutes from 8:00pm to 4:00am, then at four later times.

    Times are Eastern. The time axis is not to scale after 4:00am: the last four points are Nov 4 noon, Nov 5, Nov 7 and Nov 10, when late mail lands. Counted share tops out below 100% because unmatched precincts and non-reporting counties never come in; the model predicts their votes from the baseline.

    What was run

    How these numbers were produced

    • Model: the shared fitting functions in model_core.R (turnout, third-party share and two-party share equations; g-prior worth 3 precincts; county random effect with ICC 0.302), with the same covariates as tx_backtest.R: registrants, 2018 and 2020 turnout, sex, age 65+, Black, Hispanic and college shares.
    • Backtest: test_backtest_tx22.R rebuilds Young-Kyung's panel (as in tx_backtest_panel.R) from the Dropbox files: precincts in the 32 counties joined to votehub's 2022 results. 500 draws per checkpoint.
    • Simulated night: test_sim_night.R. tx_gov_trial.R can't read snapshot files yet, so this runs the same model core on precinct-by-mode cells (early, Election Day, mail), fitting each mode separately. Priors come from TX_precinct.parquet: expected turnout split by each precinct's 2022 mode mix, dem2, and oth_base. Vote shares are fit on every cell with votes counted; turnout is fit only on fully counted cells, and a partly counted cell is never predicted below its count. No cross-mode correlation and no mode partisan offset (delta = 0), matching the data contract's current default. 300 draws per checkpoint.
    • Limits: the simulation's swing, noise sizes, mail lean and timing are invented, and its results are built from the same dem2 the model uses as a prior, so its good performance after 9pm is partly by construction. The backtest is the stronger evidence about real-world accuracy.
    Next

    What this suggests

    • Intervals need to widen when the counted precincts don't resemble the outstanding ones. One option is a geographic effect above the county (region or urban/rural) with a prior wide enough that the first counties can't pin it.
    • Rerun the backtest with a realistic order (early votes from every county first, then Election Day precincts) once a TX 2022 or 2024 snapshot history is available.
    • Connect tx_gov_trial.R to Ethan's snapshot format and rerun Test 2 with the full model, including the cross-mode correlation.
