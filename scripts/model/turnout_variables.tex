\section{Fitted outcomes --- the same three slots, two different meanings}

The per-mode turnout slot is \emph{reinterpreted} rather than restructured, so that
$\Sigma$, the error draws, the conditional-MVN grouping and the aggregation offsets all
keep working unchanged. The reference mode's slot carries the precinct total; the other
two carry the mode composition.

\section{Switches that are off by default}

Everything above describes the shipped defaults. The variables below exist in
\file{tx\_gov\_trial.R} but do nothing unless their switch is set, which is why they do
not appear in the tables above. They are the machinery for letting a \emph{partially}
counted precinct inform $\theta$.

\paragraph{Why $\theta$'s gate is the one that is wrong.}
A completed cell's per-mode ratio decomposes exactly:
\begin{equation*}
  \log\!\left(\frac{c_{im}}{\tau^{0}_{im}}\right)
  = \underbrace{\log\!\left(\frac{T_i}{E_i}\right)}_{\text{level } (\theta)}
  + \underbrace{\log\!\left(\frac{p_{im}}{p^{0}_{im}}\right)}_{\text{composition } (\eta)} .
\end{equation*}
\emph{One} completed mode identifies the level given a composition; \emph{two} identify
both. So $\eta$'s condition (this mode and the reference) is already correct, and only
$\theta$'s \var{all\_done} is too strict --- it demands three modes where one suffices.

\paragraph{Measured status, so none of this reads as settled.}
On a simulated night whose true turnout was $0.85\times$ the prior, relaxing $\theta$'s
gate to $q_i \geq 0.5$ moved turnout from $119\%$ of truth to $101\%$, and did not
degrade the correctly-specified night. But the \emph{same} setting on the real TX 2024
backtest, where completeness is a plateau proxy rather than a feed flag, fabricated votes
--- $103.7\% \rightarrow 109.0\%$ at full count --- because $1/q$ invents the share of any
mode that is finished but not flagged. Censoring (\var{USE\_CENSOR=1}), with or without
the atom, made turnout \emph{worse} in both simulated scenarios: a lower bound can only
push the estimate up, and the error it was aimed at points down. All of these default to
off for that reason.

\section*{Two things the table makes visible}
\addcontentsline{toc}{section}{Two things the table makes visible}

\paragraph{\var{est\_turnout} enters three times.}
As $E_i$ it sets the $\theta$ prior (line 764); multiplied by the mode split it becomes
\var{prior\_tau} (line 745); and \var{prior\_tau} is then the denominator of the
\var{COMPLETE\_FRAC} plateau test (line 918). So a single vendor score sets the turnout
\emph{level}, the mode \emph{composition}, and the \emph{completeness proxy} at once. It
is the most load-bearing number on the turnout side, and none of it is computed here.

\paragraph{The fit-condition column is where the model breaks.}
$\theta$ and $\eta$ occupy the same three slots and look parallel everywhere in the code
--- same variable name \var{y\_tau}, same \var{prior\_tau} ancestry, same loop. But
$\theta$ requires \emph{all three} modes to be finished and $\eta$ requires \emph{two}.
That asymmetry is correct as identification --- one finished mode pins the level only if
the composition is assumed, two pin both --- but nothing in the naming signals it. Since
mail votes finish days after election night, \var{all\_done} is effectively never
satisfied while results are being reported, the $\theta$ equation is fitted on zero rows,
and the solve returns its prior unchanged. Measured on a simulated night whose true
turnout was $0.85 \times$ the prior, the model reported $119\%$ of truth from the first
checkpoint to the last --- which is $1/0.85$, the prior echoed back.
